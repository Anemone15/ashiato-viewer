# 足跡ビューア

iPhone の位置記録アプリから書き出した CSV（`状態,緯度,経度,時刻,精度,高度,メモ`）を読み込み、
移動の記録を地図で見たり、さまざまな形で集計したりするアプリです。
**データの処理はすべて端末内（ブラウザの Web Worker）で行い、外部には送信しません。**

## 起動

```bash
npm install
npm run dev
```

ブラウザで http://localhost:5180 を開きます。

- `data/` フォルダに CSV を置いておくと、起動時に自動で読み込みます（新しい CSV を追加・差し替えると次回起動時に反映）。
- 「データ」タブから CSV を直接読み込むこともできます（端末の IndexedDB に保存）。

### iPhone から見る

Mac と iPhone を同じ Wi-Fi につなぎ、`npm run dev` の表示にある `Network: http://192.168.x.x:5180/` を iPhone の Safari で開きます。
`data/` の CSV が自動で読み込まれ、iPhone 側にも保存されます。
（同じ LAN 内の他の端末からも開ける点に注意してください。）

## 機能

| タブ | 内容 |
|---|---|
| 日別 | その日の移動を地図に表示。移動ごとに区間（徒歩・電車…）、乗車駅→降車駅、通過駅を表示 |
| 全期間 | 全期間の軌跡を移動手段ごとに色分け／ヒートマップ。期間・手段で絞り込み |
| 集計 | 総距離、手段ごとの距離・時間・回数、月別グラフ、曜日×時間帯、よく乗る区間・駅・路線のランキング |
| 経路検索 | 乗車駅・経由駅・降車駅、移動手段、平均時速・所要時間・距離、期間・曜日・時間帯で移動を検索 |
| 場所 | よく行く場所（滞在地）のランキングと名前付け、市区町村・都道府県の制覇マップ |

## 解析の仕組み（`src/core/analyze.ts`）

1. **前処理**: 時刻順に並べ替え、重複・精度の悪い点・瞬間移動（A→B→A 型）を除去。「Point出発」は登録地点の座標なので軌跡には使わない。
2. **滞在**: 半径150m以内に10分以上いた所。長い記録の空白もほぼ動いていなければ滞在とみなす。滞在と滞在の間が1回の「移動」。
3. **区間分け**: 歩く速さ（7.5km/h未満）かどうかで分割。駅停車などの短い停止は乗り物に吸収。
4. **手段の判定**: 速度、線路（国土数値情報 N02）までの距離、停止位置が駅か、海上か（市区町村ポリゴンの外か）で判定。
   記録が途切れた区間（地下鉄・トンネル・機内）は前後の位置・所要時間・近くの路線から推定（地図では点線）。
5. **駅**: 電車区間の軌跡から 150m 以内の駅を通過駅として拾い、最初と最後を乗車駅・降車駅とする。
   事業者が変わる所（乗り換え駅）では区間を分ける。地下鉄→私鉄などの直通運転は1区間として扱う。

判定のしきい値は `analyze.ts` 冒頭の定数で調整できます。解析結果を CLI で確かめるには:

```bash
npm run analyze -- --date 2025-04-01
```

## 地理データの更新

`geodata/raw/` に元データを置いて `npm run geodata` を実行すると `public/geo/` が作り直されます。

- 鉄道: [国土数値情報 鉄道データ N02-24](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-2024.html)（`N02/UTF-8/*.geojson`）
- 市区町村: [smartnews-smri/japan-topography](https://github.com/smartnews-smri/japan-topography) `data/municipality/geojson/s0010/N03-21_210101.json`（国土数値情報 行政区域データを加工）
- 背景地図: 地理院タイル（淡色地図）
